# Автоматическое облако — версия 1

## Что работает в коде

1. GitHub Actions каждые 6 часов запускает обновление и публикацию GitHub Pages. Можно запустить вручную через Actions → Run workflow.
2. Сопоставление 33 ПК-серверов по одновременному совпадению номера и названия из API лаунчера. Домены и публичные IPv4 из DNS экспортируются автоматически. Неоднозначные адреса исключаются, не угадываются. В initial snapshot уже 66 привязок: 33 домена + 33 IPv4. Это адреса на момент проверки, не обещание их неизменности.
3. По очереди проверяются до 80 известных тем и первые страницы 6 известных серверных разделов за запуск. Новые темы отбираются по названиям, затем читаются в последующих циклах. Это не полный обход любого форума: новые разделы, внешние документы, изображения и скрытые сообщения автоматически не распознаются.
4. Из темы обходятся доступные страницы пагинации (предел 40). Если лимит достигнут, страница закрыта/пустая или формат изменился — весь прежний текст темы сохраняется. Частичный текст не заменяет полный.
5. Изменившиеся тексты обновляются как `unreviewed`; предыдущее содержимое хранится в сжатой истории revisions. Это справочные тексты, не автоматическое утверждение санкций.
6. Генерируются совместимые JSON-файлы и небольшие `.version.json`. Версия зависит от содержимого, а не от времени запуска.
7. Helper 0.3.0 через 10 секунд после настройки URL/смены сервера проверяет версию, затем раз в 15 минут. Полный пакет скачивает только при изменении версии. При ошибках остаётся локальная копия. Локальный/ручной импорт и кнопка загрузки сохранены.

## Что реально проверено в этой сессии

- API лаунчера был прочитан, совпали все 33 ПК-сервера; DNS дал 33 дополнительных IPv4, без конфликтов.
- У API обнаружены повторяющиеся additionalIps для Drake/Space/Home. Эти дополнительные псевдонимы намеренно не используются: иначе правила могли бы перепутаться.
- Обычный HTTP-сбор двух общих тем получил страницу «Проверка браузера», а не сообщения. База не изменилась; ошибки сохранены в data/last-run.json. **Нового успешного чтения правил в этом запуске не было.**
- Для расписания добавлен обычный Chromium через Playwright: он исполняет JavaScript страницы и ждёт сообщения. Никаких логинов, stealth-плагинов или прокси. Если проверка доступа/капча не завершится, чтение завершится ошибкой с сохранением старых данных. Работу этого браузерного режима на GitHub runner ещё нужно проверить после подключения аккаунта; в этой сессии он не запускался.
- Пройдены 13 тестов автоматизации, тесты базы/экспорта и Lua-проверки клиента. GitHub Actions/Pages ещё не запускались. В GTA клиент не проверен.

## Подключить один раз

Нужен **один GitHub-аккаунт**, а не одновременно GitHub и Cloudflare. В этом варианте сборщик и хостинг находятся на GitHub. Код уже подготовлен; внешние ресурсы ещё не созданы.

1. Создайте репозиторий. Для публичного сайта документы будут доступны всем. Не добавляйте пароли игроков/куки/игровые настройки. Учитывайте действующие ограничения Actions/Pages и политику аккаунта: расписание не гарантирует точное время, может задерживаться или приостанавливаться.
2. Поместите содержимое папки cloud-repository из архива **в корень** репозитория, включая `.github/workflows/cloud.yml`. Если загрузить сам ZIP вместо распакованных файлов, автоматизация не установится.
3. В Settings → Pages выберите Source: GitHub Actions. Если политика аккаунта запрещает Actions/запись workflow-токеном, это потребует разрешения владельца; отключать защиту сайта/аккаунта не нужно.
4. В Actions запустите Refresh rules and publish Pages. Workflow восстанавливает SQLite из gzip, проверяет код/данные, собирает доступные источники, сохраняет snapshot коммитом и публикует только каталог public. Конфликт git push/провал тестов остановит публикацию, а не затрёт чужие коммиты.
5. Скопируйте выданный Pages HTTPS-адрес в настройки Helper один раз:
   `https://ВАШ-САЙТ/rules/{server_key}.json`
   Для сайта репозитория нужен и префикс пути репозитория. Доменов-заглушек в скрипте нет.
6. Дальше расписание и проверки клиента работают без ручной пересылки JSON.

Паролей GitHub в Lua нет. Workflow использует ограниченный GITHUB_TOKEN своего репозитория; только job публикации имеет pages:write/id-token:write. Готового сайта/аккаунта в комплекте нет. Программно создать и опубликовать это без доступа к вашему аккаунту нельзя.

## Состояние данных

Первоначальная база: 712 документов, 3571 сообщение, 36 серверных разделов; 33 ПК + 3 Mobile. Автопривязка адресов сделана **только для ПК**, не для Mobile. Все тексты остаются unreviewed. Полнота/актуальность законодательства не подтверждены. Нельзя автоматически применять наказания на основе таких данных.

Роли полицейских/ФБР/военных разделены в полном каталоге. Текущий UI Helper по-прежнему показывает только fines/wanted у полиции/ФБР; просмотр полного армейского каталога — отдельная доработка, не незаметное изменение согласованного интерфейса.

## Сопровождение

- `public/status.json` — отчёт последнего запуска (включая ошибки).
- `public/checks.json` — удачные/неудачные проверки тем.
- `public/index.json` — серверы и количество документов.
- `public/servers/<id>.json` — полный сохранённый каталог сервера.
- `public/rules/<address_port>.json` — пакет Helper.
- `public/rules/<address_port>.version.json` — версия.
- `config/sections.json` — 318 известных разделов для поиска новых тем. Новые серверы/переименования намеренно не сопоставляются по догадке: потребуется проверка конфигурации.

Данные не выполняются как код. SHA-256 версии — маркер изменения, не цифровая подпись. При публикации важно доверять владельцу HTTPS-сайта.

Для локальной работы восстановите базу:
`python -c "import gzip,pathlib; p=pathlib.Path('data/rules.sqlite3'); p.write_bytes(gzip.decompress(pathlib.Path(str(p)+'.gz').read_bytes()))"`

Затем `pip install -r requirements.txt`, для браузерного режима `python -m playwright install chromium` (в Linux могут понадобиться системные зависимости).

- `python automation/pipeline.py --browser --limit 80 --sections 6` — полный цикл в пределах нагрузки;
- `python manage.py export` — только пересборка JSON из базы, без сети;
- `python -m unittest discover -s tests -p test_automation.py -v` — тесты сборщика;
- тестам базы нужен дополнительный пакет lupa с lupa.lua51.

Обновление существующих тем и их пагинации автоматизировано, но не все страницы разделов поиска новых тем. Автоматическое распознавание картинок, юридическая сверка конфликтующих редакций и гарантированный доступ через защиту форума не заявлены. Отчёт об ошибках следует просматривать.
